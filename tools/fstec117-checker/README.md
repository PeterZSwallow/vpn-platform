# Проверка техпаспорта ОИ по Приказу ФСТЭК России № 117

Программа с графическим интерфейсом (tkinter). Она открывает технический паспорт объекта информатизации (`.docx`), проверяет его на соответствие Приказу ФСТЭК России от 11.04.2025 № 117 и сохраняет копию документа с правками, выделенными **красным**.

## Установка и запуск

```bash
pip install -r requirements.txt
python app.py
```

В Linux tkinter может понадобиться поставить отдельно (`sudo apt install python3-tk`). В Windows и macOS он входит в установщик Python.

Без GUI, из командной строки:

```bash
python checker.py паспорт.docx [результат.docx]
```

## Что проверяется

| Проверка | Что попадает в документ |
|---|---|
| Отсутствует обязательный раздел (класс защищённости, УЗ, масштаб, модель угроз, СЗИ, аттестат и т.д., см. `rules.py`) | красное «ТУТ ДОЛЖНО БЫТЬ: … — ссылка: Приказ ФСТЭК России от 11.04.2025 № 117 (…)» в сводке в конце документа |
| Раздел есть, но нет значения (например, нет К1/К2/К3, УЗ1–УЗ3, номера сертификата) | красное замечание сразу после этого абзаца |
| Ссылка на утративший силу Приказ ФСТЭК № 17, класс К4, УЗ4, классы АС 1Г/1В… | исходный текст зачёркивается красным, под ним указано, на что заменить |
| Незаполненные поля (`____`, `[указать]`, `XXX`) | красное «Поле не заполнено» |
| Истёкший срок сертификата или аттестата («действителен до 01.02.2024») | красное замечание |
| Пустые ячейки в таблицах «параметр \| значение» | красный текст в пустой ячейке |

В начало документа добавляется строка с количеством замечаний, в конец — сводный перечень.

## Настройка правил

Все требования лежат в `rules.py` в виде списка: шаблоны поиска, текст «что должно быть» и ссылка на нормативный акт. Правило можно добавить или поправить, не трогая остальной код.

> ⚠️ Проверка ищет разделы по ключевым словам, это вспомогательный инструмент. Номера пунктов Приказа № 117 в ссылках не указаны: сверьте их с официальным текстом (publication.pravo.gov.ru) и при необходимости допишите в поле `ref`.
