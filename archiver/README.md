# zarc — архиватор с упором на максимальное сжатие

Приоритет — степень сжатия, скорость вторична. Поддерживаются любые данные.

## Использование

```bash
cargo build --release
./target/release/zarc a archive.zarc folder file.txt   # создать
./target/release/zarc l archive.zarc                   # содержимое
./target/release/zarc x archive.zarc out/              # распаковать
```

## Что уже есть (шаг 1)

- **Сплошной архив** — все файлы сжимаются одним потоком.
- **Удаление дубликатов** — одинаковое содержимое (по BLAKE3) хранится один раз.
- **Сортировка по типу** — файлы с одним расширением идут подряд.
- **xz/LZMA2 -9e** со словарём под размер данных и `nice_len=273`.
- **Проверка целостности** — каждый файл сверяется с хешем при распаковке.
- **Защита от `../` в путях** при распаковке.

Формат описан в [`src/format.rs`](src/format.rs).

## Замер (50 МБ: исходники, документация, Python-библиотеки, бинарники, копия папки)

| Архив           | Размер     |
|-----------------|-----------:|
| zip -9          | 25 061 532 |
| tar.gz -9       | 24 242 429 |
| tar.xz -9e      |  8 915 848 |
| **zarc**        |  8 874 866 |

Пока zarc лишь немного впереди xz: на 50 МБ словарь xz сам находит дубликаты.
Выигрыш дедупликации растёт на объёмах больше словаря (64 МБ).

## План

1. ~~Формат, сплошной режим, дедупликация, сортировка~~
2. Фильтры по типу: BCJ/E8E9 для исполняемых файлов, дельта для таблиц и
   несжатых аудио и картинок, словарная замена для текста.
3. Собственное ядро: смешивание контекстов + арифметический кодер (в духе paq8).
4. Пересжатие уже сжатого: deflate внутри ZIP/PNG/PDF/DOCX, JPEG без потерь.

## Почему нельзя просто «перевернуть» сжатые файлы

Перестановка байтов (задом наперёд, смена порядка байтов, разворот битов) не
меняет количества информации в данных. Сжатые данные и так выглядят как
случайный шум — в любом порядке. Помогает только распаковка внутреннего
сжатия и сжатие заново более сильным методом (пункт 4 плана).
